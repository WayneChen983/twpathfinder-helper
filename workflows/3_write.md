# 3 撰寫申請書

目標：在 `my/<編號>/` 產生五個章節檔，每章都只用使用者提供的事實。

## 動筆前一定要讀

- `knowledge/01_寫作指南/01_審查邏輯與核心觀念.md`
- `knowledge/01_寫作指南/02_格式與篇幅.md`
- `knowledge/01_寫作指南/03_各章寫法.md`
- `knowledge/01_寫作指南/04_版面、句型與常見錯誤.md`
- `data/kb/programs/<編號>.md`（簡章全文）
- `my/profile.md`、`my/<編號>/notes.md`、`my/materials/*.extracted.txt`

想看成品長什麼樣，讀 `examples/林語晴/M-2-1/`。

## 章節與篇幅

| 檔名 | 章名 | 字數上限 | 這一章要做到的事 |
|---|---|---|---|
| `0_開場.md` | 開場：一頁重點摘要 | 1,000 | 用一頁讓評審知道你是誰、缺什麼、要去做什麼、回來做什麼。可用「選擇我的 N 個理由」或四格摘要，標題要量化 |
| `1_學經歷.md` | 一、申請青年之學經歷 | 4,200 | 只寫和這個計畫有關的經歷。每段先講核心能力，再用經歷證明，段末連回計畫 |
| `2_機構了解.md` | 二、對見習機構及此項圓夢機會的了解 | 3,000 | 簡章列出的每個見習機構都要分段寫：它在做什麼、行程中會接觸什麼、和我的背景怎麼連結、我想在那裡問什麼 |
| `3_動機與期待.md` | 三、申請原因、動機及期待 | 2,500 | 第一句就講具體的落差：已經具備什麼、還缺哪一塊、為什麼是這個計畫能補上。再寫期待的收穫 |
| `4_回國後規劃.md` | 四、回國後規劃與影響力 | 2,500 | 分短期、中期、長期。短期是分享（管道、對象、形式、數量），長期是實質作為 |

簡章規定內文 15–30 頁。固定行高排版後一頁約 700 字，還要留位置給照片，所以五章合計要在 14,000 字以內。你很容易寫超過，請守住每一章的上限，把字數留給最能證明論點的內容。寫完用 `python scripts/check_draft.py my/<編號>` 確認。

## 寫法

- 第一人稱，語氣誠懇、具體，不用口號和空泛的形容詞。
- 標題用「數字＋成果」，只看標題也要抓得到重點。
- 用 Markdown：章內小標用 `###`，適合比較的內容用表格，其餘用完整段落。每個檔案從第一個小標開始，不要加前言或結語。
- 主線要一致。先決定一句話的主線（例如「技術好不好用，要到現場看人怎麼用才知道」），五章都指向它。
- 一章一章寫。寫後面的章節前先重讀前面已完成的，不要重複同一段內容。
- 每一段都要經得起這個檢驗：拿掉這段，評審會少知道什麼？

## 真實性

這一節比文筆重要，請逐條遵守。

- 只能使用 `profile.md`、`notes.md`、素材裡的事實。
- 缺的內容標成 `【待補：需要什麼】`。常見的有：人數、日期、名次、工具名稱、一個具體場景。
- 適合放照片的地方標成 `【待補：放一張○○的照片】`，一章不超過四處。
- 使用者說「打算做」「還沒開始」的事，寫成計畫，不要寫成已經在做。
- 失敗或中斷的經驗照實寫，再寫他從中學到什麼。這比含糊的成功更有說服力。
- 他沒回答的訪談題目，對應的內容留待補，不要替他選一個答案。
- 機構與行程只寫簡章有的。需要補充最新資訊的地方標成 `【待補：建議查證○○】`。簡章的數字若是去年的資料，提醒他查證今年的。
- 不要沿用 `knowledge/` 或 `examples/` 裡的任何句子、經歷或數字。

## 修改

使用者要求修改某一段時，只改他指定的地方，其他保持原樣。改完告訴他改了什麼。

## 寫完之後

1. 執行 `python scripts/check_draft.py my/<編號>`，把各章字數與待補清單告訴他。
2. 請他逐項補上待補的內容。他補了之後，把對應的 `【待補：…】` 換成實際內容。
3. 提醒他可以接著做「模擬評審」或「放照片並產生 Word」。
